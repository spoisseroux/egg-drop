## Decision and concrete portable mount proposal

If source-only effective hulls and nonempty payload hashes match the native reference, retain XML mapping and record fresh-build hydration proof; no asset replacement is warranted. Still preserve actual native checkpoint/export as evidence. If ray mismatch or missing/changed hull payload remains, use the verified native model as canonical build input after independent review and root coordination.

For the latter, stage a new authoritative assets/world/WorldAssets.rbxm from the verified export and change ONLY ServerStorage.WorldAssets $path to it. Keep generated WorldAssets.rbxmx as staging geometry input. Do not overwrite or disguise the native binary as XML. Update builder behavior so it cannot silently replace an approved native model: collision readiness proof must bind exact generated geometry/mesh IDs/raw sizes/transforms and native file SHA plus per-solid PhysicalConfigData SHA. Changed solid geometry invalidates proof and blocks final canonical build until CreateMeshPartAsync Precise→ApplyMesh→native export→roundtrip verification is repeated. Visual-only metadata changes need explicit payload-preserving re-export/proof policy, never stale bounds substitution. Avoid runtime asset-fetch/rebuild dependency if a portable native source works.

Before adopting: native-only Rojo model conversion, isolated native import/rays, fresh complete Rojo place import with the native mapping and no runtime rescue, exact component/name/count/bounds/material checks, positive probe coverage for each rebuilt mesh, park ground-ray suite and normal player collision smoke. Save actual Studio locally as unpublished .rbxl checkpoint before any source commit. No experience publishing.

Official engine basis: MeshPart.ApplyMesh copies CollisionFidelity WITH internal collision geometry; AssetService.CreateMeshPartAsync accepts CollisionFidelity; SerializationService roundtrips instances through native buffers. A token alone is not a proof of the stored geometry.
